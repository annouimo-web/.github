# Annouimo 网站重构总纲

本文记录已确定的重构方向，作为组织内各工程的共同依据。待定事项不构成实施要求。

## 基本原则

- 简化优先：以实际价值决定功能去留，不以复刻旧站为目标；敢于删除低价值功能，不为尚不存在的需求预建复杂设施。
- 静态优先：公开页面全部静态生成，充分利用 Cloudflare Workers Static Assets；动态数据按需通过 API 获取。
- 统一而不耦合：统一公开网站与前端设计，保持业务服务独立，允许未来应用按需接入或独立运行。
- 内容与工程分离：创作内容不应要求日常操作网站工程。
- 先预览后生产：在预览环境验证后再发布；保护现有数据，保留回滚能力。

## 整体架构

- 保留 `www.annouimo.com` 为主网站，根域名跳转至 www；其他子域名按应用职责分配。不要求兼容旧域名及旧 URL。
- `website` 作为统一前端工程，整合原主页、博客、讲义、陈列室；公开站静态生成，私人管理入口与公开站分离。共享设计资源，按职责部署。
- 保留 `writing` 与 `notes` 内容仓库；讲义保留独立开发、测试与预览能力。网站导入已确认发布的内容，发布流程应自动化、可追溯。
- 后端按业务划分，负责业务规则、权限和数据，前端通过明确的 API 接入。优先利用 Cloudflare 原生能力，避免不必要的中间层。
- 私人管理入口及接口必须进行身份认证与授权；生产和预览的写入权限、数据资源必须隔离。

## 陈列室

- 保留现有业务规则、私人管理功能与历史数据，不因展示方式变化而重建数据库。
- 公开展示迁入统一网站，列表数据通过 API 按需加载。
- 取消公开作品独立详情页，不为此引入 SSR 或动态页面路由；轻量详情弹窗待定。
- 删除公开功能不等于删除底层数据。

## 设计

- 统一公开网站的视觉语言、布局和导航，继承既有设计中的有效成果，不盲目照搬。
- 重新审视整体名称和图标，认真设计主标识，不默认沿用纯字母图标。
- 公共设计资源集中维护，业务组件按职责归属，避免过度抽象。

## 待定

- 具体仓库边界、前后端框架及目录、包管理工具。
- Worker 划分、Service Bindings / BFF、API 契约及权限传递的具体实现。
- 内容导入契约、版本锁定策略、自动发布触发及集成预览机制。
- 设计资源跨仓库共享方式、最终名称与品牌标识。
- 首页、主导航、项目栏目、归档与搜索的具体范围。
- 陈列室轻量详情弹窗及非核心功能取舍。
- 测试与验收标准、迁移顺序、生产切换及旧工程归档计划。

待定事项在相关决策明确后再更新本文；实现细节留在相应工程文档中。
